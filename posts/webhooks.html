What is a webhook?

It's when one app automatically tells another app "hey, something just happened", so the other one doesn't have to keep asking.

The easiest way to get it is a pizza order

Without a webhook: you keep calling the restaurant. "Is it ready yet?" "Not yet." "Now?" "Nope." Most calls are a waste of time, and you still find out late.

With a webhook: you leave your number once. When the pizza is ready, they call you. That's it.

In software it works the same way. Instead of your app asking for the status again and again (that's called polling), you give the other service a URL once. When the thing happens, it sends a request to that URL with the details.

You've probably used this already without knowing:
→ you pay for something and the order status updates right away
→ you push code to GitHub and the deploy starts by itself
→ a customer replies and your support tool gets the message instantly

For devs, three things that are easy to forget:
→ check the signature (HMAC): the URL is public, so anyone can send fake events
→ answer 2xx fast and do the heavy work in a queue, or the provider gives up and retries
→ make it idempotent: the same event can show up twice
