import { useEffect } from 'react'; useEffect(() => { const socket = connect(roomId); // missing cleanup… }, [roomId]);

Your useEffect isn't broken. React is testing it.

In development, Strict Mode runs your effects twice on purpose: mount → cleanup → mount again.

Most devs see the double call and reach for a useRef flag to "fix" it. That's backwards — the double run is exposing a real bug.

If your effect subscribes to something without cleaning up, you now have two subscriptions. Two intervals. Two socket connections. In dev it looks weird. In production, it's a memory leak waiting for a remount.

The fix is always the cleanup:

useEffect(() => {
  const socket = connect(roomId);
  return () => socket.disconnect();
}, [roomId]);

With proper cleanup, the double mount is a no-op. Without it, your component leaks every time it remounts — and React is remounting components more than ever (hello, <Activity>).

Strict Mode isn't the bug. It's the bug detector.
