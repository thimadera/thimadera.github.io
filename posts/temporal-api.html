JavaScript's Date object has been breaking developers' brains for 30 years.

It's one of the oldest, quirkiest parts of the language. Most of us just learned to work around it instead of questioning it. Two classics:

Months start at zero.
const d = new Date(2026, 0, 15);
d.getMonth(); // 0
January is month 0. December is 11. It's inherited from an old Java API from 1995, and pretty much every JS developer has shipped an off-by-one bug because of it.

Time zones are a nightmare.
Add a day to a date, and daylight saving time can silently turn "+1 day" into "+23 hours." Schedule a call across time zones and there's a real chance it lands at the wrong hour. Ask anyone who's ever set up an interview between São Paulo and New York.

And that's just two. Inconsistent parsing, objects that quietly change when you don't expect them to, no real time zone support... the list goes on.

The good news: JavaScript just got a real fix, built directly into the language. It's called Temporal, and after about 10 years of work, it's officially here:

const d = Temporal.PlainDate.from('2026-01-15');
d.month; // 1, counts the way humans do

It fixes the classics above and a long list of others: real time zone support, no silent changes, consistent parsing, and an overall saner API. It's native to the language, so there's nothing to install.
